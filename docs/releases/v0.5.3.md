# lueya v0.5.3 — artist search, reliable result selection and artwork

Owner's v0.5.2 feedback:
- "кино" returned songs named Kino by unrelated artists, while
  "кино - ..." found the desired recordings.
- Hovering/scrolling search results interfered with click handling.
- Some tracks returned 403 at the raw audio source; others played.
- Keychain prompted after update; Retry preserved the saved Yandex session.
- Optional album artwork would improve the player.

## Changes

- A deliberate Songs / Artists switch; selecting an artist opens only that
  artist's bounded, authenticated track list.
- Four result rows per page with clear Previous/Next controls, avoiding
  a ScrollView hit-testing area that could swallow mouse events.
- Small album artwork from the public approved `avatars.yandex.net` cover
  CDN, fetched with an ephemeral, redirect-free, cookie-free and cache-free
  HTTPS session, bounded by response size and dimensions. Failure is benign.
- Explain track-specific raw-source 403 as provider denial instead of
  implying a global player, Keychain or region failure. No DRM bypass.
- Keep the v0.5.2 OAuth/Keychain service and account, stable certificate,
  immutable release assets and memory-only online streaming unchanged.
  The legitimate macOS legacy migration prompt can still appear once;
  select "Always Allow" only when the application identity is expected.

## Verification and limits

Synthetic tests cover Cyrillic artist matching, selected artist's tracks,
untrusted artwork templates and invalid artist IDs. The owner must still
test actual source availability, clicking all result rows, Keychain ACL
continuity, artwork and playback on a physical Mac. Provider terms and
unofficial endpoint limits are unchanged.

Apple Silicon arm64; macOS 26 or later. Pinned self-signed research
certificate, not Apple Developer ID, not notarized.
